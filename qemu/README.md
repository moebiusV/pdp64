# pdp64 on QEMU

`qemu-system-pdp64 -M pdp64-virt -kernel prog` runs the programs that `sim64` runs, with the same results.
This directory holds everything we write for it; `~/claude/qemu-src` (a QEMU v11.1.2 checkout) and
`~/claude/qemu-build` are scratch places where it is built, never committed here.

## Install, build, run

    qemu/build.sh [-j N]        # install.sh + configure + ninja; the result is ~/claude/qemu-build/qemu-system-pdp64
    qemu/install.sh [qemu-src]  # only put the target into a QEMU tree (idempotent)
    qemu/sync.sh [--check]      # refresh / verify the generated copies in target-pdp64/gen

    build/as64 -o t.o t.s && build/ld64 -o t.x t.o
    qemu-system-pdp64 -M pdp64-virt -display none -kernel t.x; echo $?

The exit status of the qemu process is the program's: `trap #0` / `halt` give r0 & 255, a fault gives 139 (with a message and
the registers on standard error).  `tools/check-qemu.sh` runs tests/sim/*.s under it; `PDP64RUN=qemu tools/pdp64test-all.sh`
runs the C tests (PDP64CCOM needed).  `tools/check-all.sh` includes check-qemu when the binary exists.

## Layout

- `qemu-core.patch`: the changes to QEMU's own files (SysEmuTarget enum, QEMU_ARCH_PDP64, poison list, EM_PDP64 = 0xF064 in
  elf.h, and the target/hw Kconfig and meson lists).
- `target-pdp64/` becomes `target/pdp64/`; `hw-pdp64/` becomes `hw/pdp64/`; `configs/` is copied to `configs/`.
- `target-pdp64/gen/`: copies of common/pdp64exec.c/.h, common/calib.c/.h, as64/fmtp.c, as64/fmt.h and the generated
  build/pdp64-parser.c and pdp64-consts.h.  Generated by `sync.sh`, never edited; `sync.sh --check` fails if they are stale
  (install.sh and check-qemu.sh run it), so the grammar stays the only source of the decoder.

## Memory map (pdp64-virt)

| range                       | what                                                  |
|-----------------------------|-------------------------------------------------------|
| 0x00000000 .. ram_size      | RAM, default 128 MiB (`-m`, at most 256 MiB)          |
| 0x10000000 .. 0x1fffffff    | reserved for devices (none yet)                       |

No MMU: addresses are physical.  Anything else is a fault.  `-kernel` loads an ELF executable (machine 0xF064, little-endian,
as ld64 writes it; text at 0x10000) and starts at its entry point with r14 (sp) = top of RAM minus a page.

## Design

Nothing is written twice.  The meaning of every instruction is in common/pdp64exec.c, the decoder is generated from
spec/pdp64.hbnf.in; the QEMU target only supplies the host's side of `struct pdp64_env`.

- `CPUPDP64State` embeds `struct pdp64_cpu`, so the core works on the CPU state directly.
- One instruction per translation block: the translator reads the first parcel (the top two bits give the length), stores pc,
  emits a call to `helper_exec` and a `lookup_and_goto_ptr`.  `helper_exec` runs `pdp64_step()`, which fetches, decodes and
  executes from guest memory.  Because the block contains no decoded instruction, self-modifying code needs no special care.
- The core's ld/st hooks check alignment and mapping (as sim64 does) and then use `cpu_ld*_le_data_ra` / `cpu_st*_le_data_ra`
  with the helper's return address.  A fault prints what/pc/addr, requests shutdown with code 139 and leaves the CPU loop.
- `trap #n` (exit, write, read) and `halt` are the same stand-in as sim64's; the exit goes through
  `qemu_system_shutdown_request_with_code`, so the host process status is the program's.
- The core and decoder are built as a separate static library with `-w` and the symbol renames of tools/build-as64.sh
  (QEMU's strict flags would reject the generated parser).

## Deliberately not done

No MMU or privileged state, no devices (no serial: programs use `trap #1`), no interrupts, no TCG fast paths (every instruction
is a helper call: correctness first, speed later), no user-mode `qemu-pdp64`, no gdbstub, no disassembler, no migration state
(vmstate), no multi-CPU.
