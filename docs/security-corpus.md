# The security corpus

[← pdp64 index](../README.md)

*The owner's rule (2026-11-19, errata 201): "all security holes, information bleeds must be dealt with and prevented, even if only to have it in the corpus of assembler to test that the implementation doesn't have these holes."* This file is the index of that corpus: one row for each hole or information bleed, the probe program or programs that look for it, what an implementation that has the hole does, and whether the current implementation has it.

## What the corpus is

A **probe** is a small assembly program that looks for exactly one hole. It exits with status 0 when the implementation does **not** have the hole, and with the number of the first failed check otherwise. Every probe has a control (a check that the machinery of the probe works) so that a probe that cannot fail would show itself.

* Probes that pass on the current implementation are ordinary tests: `tests/sim/sec-*` (they run on `sim64` and on the QEMU machine; `NAME.flags` says `-K`, `-H` or `-x` as for every test there) and `tests/qemu/sec-*` (QEMU only: they need page tables or the IOMMU). `tools/check-sim64.sh`, `tools/check-qemu.sh` and so `tools/check-all.sh` run them with the other tests, and a failure there is a regression.
* Probes that **find** a hole on the current implementation are in `tests/sec-open/sim` and `tests/sec-open/qemu`. They are kept out of `tools/check-all.sh`'s sim64 and QEMU runs, because a found hole is the corpus doing its job and must not turn the build red. `tools/check-sec.sh` runs them on sim64 and QEMU and prints `FOUND name (where): failed check n` for each, `PASS` for one that now passes, `BROKEN` for anything else (it does not assemble, it crashes, it times out); it exits 0 unless something is BROKEN. `tools/check-sec.sh --check` also compares the result with this index and fails if a FOUND probe is not listed here as FOUND, if a probe that passes is still in `tests/sec-open` or listed as FOUND, if a probe file is not named in a row, or if a row names a file that does not exist; `tools/check-all.sh` runs this mode. When a hole is fixed its probe moves to `tests/sim` or `tests/qemu` and its row becomes `pass`.
* The probes with regular shape are written by `tests/sec/gen_sec.py` (with `tests/sec/secgen.py`: the prelude, the table of vectors, the handlers) and are marked GENERATED; run it with no argument to write the files where they belong (the set `OPEN` in it says which go to `tests/sec-open`). Rows that name a probe without the prefix `sec-` are earlier tests of `tests/sim`, `tests/qemu` or a `tools/` check that already probe the hole; they are indexed here and not copied.
* Writing a probe: a handler for every vector records the cause, the return address and the address of the exception and returns to the address in r13; the probe sets r13, runs the instruction, and compares. In a probe the scratch register of the check macros is r17 and the handler uses r11 and r12 only. (A first version of the probes used r11 as the scratch of the checks and compared a register with itself: the non-vacuity runs below caught it, and are the reason they are part of the corpus.)

## The classes

1. **privilege**: every sensitive instruction and system register from a lesser mode (user; a guest kernel with the hypervisor strap);
2. **information bleed**: any register, hidden register, bank, cache or memory that keeps another context's data after a mode change, an exception entry or return, a world switch, a reset or a change of address-space number;
3. **memory protection**: the user-access guard, user access to kernel pages, device space, the guest's vector fetch and table walk, stage-2 permissions;
4. **DMA**: a device with no mapping, with a stale one, a device reaching another device's registers;
5. **restart and precision**: a faulting instruction leaves no effect; a block restarted gives the result of an uninterrupted run (class "2/5 vector block" for the holes of the vector unit, which are both a bleed and a restart question);
6. **undefined behaviour**: reserved encodings, reserved bits, unassigned registers: all defined to fault or read as zero;
7. **denial of service**: a lesser mode stopping a more privileged one.

## What was found (the FOUND rows, in plain words)

Run on the current implementation, 2026-11-19, and again on 2026-11-25. Five holes remain; the probes that find them are three in the sim64 model and the QEMU machine alike (they share one executor) and two on QEMU only.

1. **A guest reset that only rewrites stage 2 keeps the old translations (SEC-B14).** The hypervisor changes a stage-2 entry of a guest whose translation is off and enters it again; the guest still reads the old page. The rule is that only TLBIA, a change of MMUCTL, of the stage-2 root or of its enable discards a guest's cached entries; a reset is not an event the hardware knows. The same program that writes MMUCTL as 0 first passes (SEC-B13). This is the leak of the Linux CVE the owner asked about, left to the hypervisor's care.
2. **DMA into another device's registers (SEC-D01).** A device whose table maps a device address onto the timer's page wrote the timer's compare register. The unit checks read and write permission, not what the target is. With a message-signalled interrupt path this is how a guest-assigned device could forge interrupts.
3. **An exception between VCLR and VEC changes the answer (SEC-V01).** The accumulators come back as plain registers: a silently wrong result with no fault, from an event the program cannot see.
4. **An accumulator block that updates memory in place is wrong after a page fault (SEC-V02).** The block restarts from its entry and does the first strip's work twice: 4 of the 8 lanes were 2 instead of 1.
5. **The hidden record of an aborted block is found by address, not by context (SEC-V03).** Context B, running the same code at the same address after context A's block was aborted, gets A's accumulator naming and computes running sums.

Closed on 2026-11-25 (the probes moved to `tests/sim` and the rows are `pass`): **the kernel's scalar registers visible to the user after the return (SEC-B04)** and **the floating-point flags carried from one context to the next (SEC-B05)**. `RTI #mask`, `RTT #mask` and `GENTER #mask` clear every register whose bit of the mask is zero in the return itself, and a write of ASID, PTBR or GTBR clears the floating-point flags; the probes (`sec-regs-carry`, `sec-rtt-clear`, `sec-genter-regs`, `sec-fpsr-carry`, `sec-fpsr-gtbr`) were shown able to fail below.

Nothing else was found: 57 holes do not exist on the current implementation, according to probes that fail when the model is broken the way the hole would break it.

## What cannot be tested here (the N/A rows)

* **Timing, cache, speculation, memory chips, power** (SEC-B20 to SEC-B22): the simulator and the QEMU machine have no time, no cache, no predictor, no DRAM; the only architectural form (a faulting load yields no data, SEC-B17) is tested.
* **One core**: SEV, the event state, invalidates broadcast to other cores and their timing (SEC-P10, SEC-P12, SEC-B19, SEC-X03).
* **Not built or not decided**: a device that writes a reserved block (SEC-D07), nesting (SEC-P09), the second root register (SEC-M09), a translation regime for the hypervisor (SEC-M10), the interrupt-message path (SEC-D06), the memory-type combining (SEC-M05; the model has no data cache), W^X (SEC-M03: the page bits allow it, enforcing it is policy), a long block that never completes (SEC-V04: the executor runs a block whole and takes no interrupt inside it).
* **The IOMMU details the model cannot hold half done** (SEC-D08, SEC-D09): its bus is synchronous, nothing is in flight, there is no cache between a core and the unit, no switch, no translated requests.
* **No clock instruction** (SEC-B23): an absence cannot be probed.
