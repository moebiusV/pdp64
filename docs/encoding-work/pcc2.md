## 1. -xccp, -xtailcall (done)
Both flags were parsed in main.c and read by nothing (commits 5ca51a27 / a3ee00b9 added only the flag; the SSA branch has only simple_cp, "should be replaced with conditional constant propagation someday"). Now: -xccp = conditional constant propagation on the temporaries (mip/optim2.c ccp(), per-block lattice, executable edges, constant CBRANCH folded; MI, off elsewhere, on for the new targets): corpus -1,908 B / -788 insns, dynamic effect <0.1%. -xtailcall (pdp64 peephole): indirect tail calls (call (rN) -> jmp (rN), calli -> jmpi) and a call;ret in the middle of a function (the old test needed the ret that carries the frame size): -268 B. -xno-NAME now reaches the target's own optimizations (TARGET_XNO).
## 2. The sj = VAX optimizations (done as far as applicable)
Inventory of arch/vax (original table 33c978a9 + later -xdmr bits) and mip/ in the doc, split MI vs BE for both Ritchie (dmr) and Johnson (sj), with pdp64 status per item. Ported (text passes in peep.h, -xno-NAME each): autoinc/autodec (+strided), sob and the rotated while(n--), field extract/insert (extb/extzb/insb), inc/dec/neg/com and addm/subm/bicm/bism on memory, bic, jump tables (casel analog, 8-byte entries, table after the ret), tree rewrites: signed division by 2^k and pointer difference as shifts, signed int division/remainder by constants as multiply+shift. Added beyond the VAX: set cc for comparison values, min/max/abs, lea for mul 5/9, scaled index through a long/unsigned long conversion (bs_ec's inner loop: -31% instructions). Already present or n/a: index mode, lea, inc/dec, codes reuse, calls/ret (different ABI). MI Johnson parts are always on (no flag) and were checked, not changed. MI changes: ccp (only with -xccp), iscasel accepts the pdp64 table jump, extern. Other back ends: amd64 built, compiled the new test programs with and without -xccp, all correct; vax built and compiled with -xccp (no VAX simulator: not run). r20 output byte-identical on all 841 files after every commit.
## 3. -xssa benchmark (done)
FOUND AND FIXED: -xssa miscompiled Lua. Bisected to lapi.c; the bug was in pp_avail (phase 3): after a register copy the availability key of the destination still said "load from (dest)", so the next movq (r0),r0 was dropped (index2value). Fixed; with -xssa all six now run on /16 and /32 (12/12).
Timing model (my own sweep with sim64 --timing, 7 models: issue 1/2/4 x fetch 4..64, one with 16 KB caches): -xssa costs +3.2..3.9% cycles in total on /16 (per program +0.3..+6.0%, never a win), +4.0..5.1% on /32 (lz4, bs_hash, bs_ec run); executes +5.2% (/16) and +4.7% (/32) MORE instructions, +6.1%/+7.7% more bytes, +2.0% static. Decision: OFF on both targets. Fetch vs execute: fetch-wait is 0-8% of cycles from 4 bytes/cycle up (knee at 2 B/cycle from the timing agent's sweep), execute-wait 21-43% (load-use); issue 1->2 takes 16% off, 2->4 another 2.9%; widening fetch 4->16 only -0.3%. Size-for-speed passes (divp2 +2..6 B, divmagic +6..10 B, jtab) measured on micro-benchmarks and lua: divp2/divmagic 30-67% fewer cycles, jtab -3.4..-5.0% cycles on lua and 806 B smaller.
## 4. Missing optimizations
Done: tail calls, ccp, jump tables, strength reduction of division/pointer difference/small multipliers, redundant-extension unchanged, scaled-index through conversions, spill-reload hoisting (-m hoist, off: it finds almost nothing, the loops that reload have no free register). Not done (reasons in the doc): loop-invariant motion of lea sym/constants and induction-variable strength reduction (no free registers in the hot loops; allocator has no live-range splitting), 64-bit/unsigned division by constants (needs mulh/mulhu tree operators), the unaligned memcpy idiom as movuw/movul/movuq (lz4's LZ4_read16: 10% of lz4's instructions), loops to mset/mscn.
