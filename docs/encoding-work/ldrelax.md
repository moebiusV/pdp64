## 1. Design (what was built)

**Object format.** `as64 -m pdp64/16|32 --relax` (opt-in; default off, so every old object and test is byte-identical; pdp64/r20 refused with --relax). e_flags: `EF_PDP64_RELAX` 0x10, `EF_PDP64_NOADJ_TEXT` 0x20 (as64/relocs.h).
The *site* of a relaxation is the existing relocation (INSN_PC / INSN_BR / INSN_ABS), which `--relax` now also records for references to labels of the *same* section (value already in the instruction, so the unrelaxed link is the same program), plus new `R_PDP64_ALIGN` (type 6; r_offset = start of the padding, symbol 0, addend = padding bytes << 32 | alignment) on every `.even/.align/.pool` padding in .text. Pool loads are sites too (against the local `.LCn`).
Anything in .text that depends on a distance and is not a relocation (a difference of two .text labels as a number, a `d(pc)` as a number, an instruction with two address operands) sets NOADJ_TEXT: the linker leaves that object's .text alone.
No second "relaxation record": one relocation per instruction says where the field is, what it refers to and in which unit; the linker re-derives everything else from the codec.

**ld64** (ld64/relax.c, included by ld64.c; ld64.c's layout/relocation code was reworked around one mapping function): per input .text section a sorted list of sites; an old offset x maps to x + sum(cur - len0) of sites ending at or before x. *Every* address goes through this: symbols (global and local), entry, relocation places P, relocation addends of section symbols and of `sym+k` (mapped as old offset value+k), D64/D32 in .data and .text (tables of code addresses), pool references, the start of later input sections. Algorithm: start every instruction site at its shortest form (codec: decode the assembler's instruction, address operand 0, `enc_len`); round = layout (paddings recomputed from positions, class bases, .data on the next page) + for every site measure S+A-P on that layout and grow to the shortest form of at least the present length (`enc_encode_n`); repeat until nothing grows (2-3 rounds on everything measured). Lengths only grow (bounded by 6 bytes), paddings are a function of the layout and not state, so it terminates; at the end the layout the values were measured on is the layout written, so every field fits (else a link error naming the symbol, same text as before). Growth from the shortest (the assembler's own scheme) rather than shrinking from the assembler's lengths because the cross-class distances (text->data across the page rounding) and paddings are not monotone under shrinking. Each rewritten instruction is decoded back and compared with the assembler's (mnemonic, registers, all operands but the address) before it is accepted. Options: `ld64 --no-relax` (link relaxation objects exactly as assembled; byte for byte the plain link, checked), `--stats` (sites by category), `--dump-map f`. Hard parts done: intra-section branches/pc-refs the assembler resolved (kept as relocations in --relax objects), alignment/pool paddings, tables of code addresses, symbols, entry. Not applicable here: debug info and symbol sizes (as64 has no .size / debug).

**Not done / limits (also in docs/relaxation.md 5):** r20 left alone; the compiler driver must pass `--relax` (default stays off, my choice, errata 89 item 1); cbCC expanded to cmp+bCC is not un-expanded; a label directly before an `.align` that needed 0 bytes moves behind the padding if it grows (nothing in the compiler's output has that); NOADJ_TEXT objects are not relaxed at all.

## 2. Reaches (exact, from the tables; field bits x unit)
pdp64/16: call 4B: 64 KiB / 256 KiB / **1 MiB** (PC16/18/20 in parcels), 6B +-2 GiB; jmp 4B 64 KiB only; movcall 4B 64 KiB only; br 2B 64/256/512 B, 4B 64 KiB; bCC 2B 64/128/256 B, 4B 64 KiB; cbCC 2B 32/64 B, 4B 256 B..16 KiB, no 6B form; sob 4B 64 KiB; lea / movq sym / ALU sym 4B 2 KiB / 8 KiB / **32 KiB** (bytes), 6B PC32 or A32. pdp64/32: same except br 2B 64/256 B, bCC 2B 64 B, cbCC 2B 32 B. **The 4-byte call reaches +-1 MiB, not the +-2 MB of errata 87 / the proposal** (20 bits x 2 bytes); there is no 2-byte call/jmp/lea, so the shortest external call is 4 bytes.
Cannot be reached by relaxation: calls/jmp/movcall/lea beyond those reaches (6 bytes stay; in Lua, 91 KB of text, 284 `movcall` and 6 `jmp` stay 6 bytes because their only 4-byte form is +-64 KiB; zlib 12 movcall), data `lea` farther than 32 KiB (all but 402 of the 12,288 in the 258 KB memcpy-a2 file), indirect calls (calli/jmpi through memory or register, no PLT/GOT), expanded cbCC, the absolute forms (value > 2 KiB at text 0x10000), NOADJ_TEXT objects, and anything beyond +-2 GiB (link error).

## 5. Findings worth the author's attention
1. 4-byte `call` is +-1 MiB (errata 87's +-2 MB is wrong by 2x); `jmp` and `movcall` have only the +-64 KiB 4-byte form, so in a program over 64 KiB their relaxation stops (Lua: 290 sites, 580 bytes = 0.6% of its text); `lea`/pc-relative loads only +-32 KiB. A PC18/PC20 form for movcall/jmp would pay in programs over 64 KiB.
2. Default: `--relax` is opt-in; the compiler driver / build scripts need to pass it (one-line change); flipping the as64 default would also pass all tests (check-sim64 runs everything relaxed), I did not do it because it changes every object's bytes.
3. as64's behaviour is unchanged without --relax. The codec got one field (`efield.oi`), nothing else changed there.
4. Sim time for the Lua differential is address-dependent (pointer hashing) - not a relaxation bug.
