# docs/: the map of the documents

[← pdp64 index](../README.md)

The pdp64 is one CPU: thirty-two registers and a prefix-coded encoding (the author, 2026-11-10; errata 122, 123). **The source of truth is the ledger, [`decisions-and-status.md`](decisions-and-status.md)**, with the author's words in the [decision register](decision-register.md) and the numbered decisions in [`errata.md`](errata.md) (the later entries win over older text). All documents and the manual follow it. This page says what each document is, in three classes:

* **Current**: describes how the architecture or the tools are meant to be; kept correct and consistent with the ledger.
* **Record**: a dated study, proposal, research report or decision process. Valuable as history, not rewritten; each carries a banner on its first line saying its date and what is out of date. Where it disagrees with the manual or the ledger, they win.
* **History**: superseded (the original encoding r20, the sixteen-register iterations, the family of three encodings). Kept for the record; not a way to learn the current design.

The pdp64's earlier iterations, r20 and pdp64/16, are in the git tags `pre-single-cpu` (manuals and tools) and `pre-code-removal` (code). The opcodes may still change when the open items are decided and the encoding optimiser is run again; no current document states opcode numbers or bit layouts in prose (see [`../handoff.md`](../handoff.md), the order of work).
