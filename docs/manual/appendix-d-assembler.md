# Appendix D. The assembly language and the object format

[← manual index](00-index.md)

**The assembler's source layout is the V7 assembler's, `as`; its lexical rules are C's.** This appendix is the syntax of a source file: lines, labels, numbers, strings, operators, directives, registers, the operand modes, the mnemonic conventions and the object format. The grammar itself is `spec/pdp64-asm.hbnf`; the source of this appendix is [`asm-syntax.md`](../asm-syntax.md). The mnemonics are in the [instruction dictionary](dictionary/index.md).

The grammar is `spec/pdp64-asm.hbnf` ([hbnf](https://github.com/moebiusV/hbnf) text rules).

- **Lines.** One statement to a line. `;` or `//` starts a comment that runs to the end of the line.
- **Labels.** `name:` defines a label; `1:` defines a numeric label, referenced as `1b` (the nearest one before) or `1f` (the nearest after).
  `sym = expr` assigns. `.` is the location counter. Names are letters, digits, `_`, `.` and `$` and any non-ASCII code point (`café`, `ループ`); a name may start with a digit as long as the whole bareword is not a number (`3dfx:` is a label; `3`, `0x3d`, `0b101`, `0o17` are numbers; `1f` and `1b` are local
  references), and a bareword of digits only is a numeric local label. Names are case-sensitive and never truncated. ELF symbol names are any bytes, so a name with other characters is written in double quotes (`"odd name!"`). A mnemonic or register name cannot be a label, and neither can `r` followed only by digits: `r16` is an error, not a name (`r2d2` is a name).
- **UTF-8.** A source file is UTF-8, and the parser refuses anything that is not (a stray byte, an overlong form, a surrogate, a truncated sequence),
  in names, strings, characters and comments alike; a NUL byte is refused too. In a string, UTF-8 text is copied as bytes and `\u00e9`, `\U0001F600` are written as UTF-8;
  `'é'` is the code point 0xE9, as is `'\u00e9'`.
- **Numbers and characters** are C's, with one refusal. A number is decimal (`255`), or has a prefix: `0x` for hexadecimal (`0xff`), `0o` for octal (`0o377`) and `0b` for binary (`0b1010`). The prefixes are lower case, and a lone `0` is zero. C reads a leading zero as octal and a reader of decimal reads it as decimal, so `010` has two honest readings and I give it none: a number with a leading zero is an error that names `0o` (`077` is refused; `0o77` is the octal number and `77` the decimal one). Characters are `'a'`, `'\n'`, `'\x41'`, `'\101'`.
- **The immediate** is `$expr`: the dollar sign says that the value of the expression is the operand, and not the contents of the address it names (`mov $5, r1`, `add $-1, r2`, `cbeq r3, $0x7f, label`, `mov $table+8, r4`). It is the V7 assembler's spelling, and it survives the C preprocessor, which reads a `#` before a macro parameter as the operator that makes a string, so a hand-written `.S` file can put an immediate in a macro. `#expr` is accepted as the same thing. A register after the marker (`$r1`) is refused, for a register is not a value. `$` is also a letter of a name after its first character (`a$b`); a name that begins with it is written in double quotes, and a `$` anywhere else is an error: the location counter is `.` (`.word .-start` is the distance from the label `start`, and `.fill n, 1, 0` writes n zero bytes).
- **Strings** are `"text\n"` with C's escapes (`\n \t \r \a \b \f \v \0 \\ \' \" \xHH \ooo`), in `.byte` and `.ascii`.
- **Operators** are C's: `* / % & << >>` and `+ - | ^`, unary `- ~ !`, and parentheses. `/` is division. `*`, `/`, `%`, `&` and the shifts need
  constants; `+` and `-` accept one relocatable symbol, and the difference of two symbols of one section is a constant.
- **Other spellings**. Besides the forms above, as64 accepts the spellings of the assemblers that other people know, wherever they do not change what a form above means: `//` also starts a comment; `base+expr` and `base-expr` (a base register and a displacement) for `expr(base)`: `r5-8` is `-8(r5)` and `sp-8` is `-8(sp)`; `(base,index,scale)` and `expr(base,index,scale)` for `expr(base)(index*scale)`; `name equ expr` for `name = expr`; `db` and `dw` for `.byte` and `.word`; `name proc` (it defines the label `name`) and `name endp` (it does nothing); `[ ]` to group, like `( )`; the binary `a ! b`, which is `a | ~b`, and the unary `<x` and `>x`, the low and the high byte of x. `^` stays the exclusive or and `@name` the absolute mode: a spelling that would take them over is not taken.
- **Conditionals.** `.if expr`, `.else` and `.endif` assemble or skip the lines between, the expression a constant of symbols already assigned (the assembler does them in its passes). There are no macros and no `.rept`: neither GCC, LLVM nor pcc writes them, and the language is in the grammar; a hand-written assembly file that wants them uses the C preprocessor.
- **Directives.** `.text .data .bss .globl .comm .byte .word .long .quad .ascii .even .align .space .lpad .pool`. `.word` is 16 bits, `.long` 32, `.quad` 64
  (the ISA's PDP-11 terminology). `.align n` aligns to n bytes (a power of two).
- **Registers.** `r0`..`r31`; `sp` is `r14`, `fp` is `r13`. `pc` and `dp` appear only as a base: `d(pc)`, `d(dp)`. A register is written as it is, with no sigil: `r1`, not `$r1` and not `%r1` (`%` is the modulo operator and nothing else).
- **Operand modes** (ISA section 5): `rN`; `$expr`; `@expr`; `expr(rN)` and `(rN)`; `expr(rN)(rX*s)` with `s` 1, 2, 4 or 8; `expr(pc)`; `expr(dp)`;
  `(rN)+` and `(rN)+d`; `-(rN)` and `(rN)-d`; a bare expression is a PC-relative reference.
- **Mnemonics** are lowercase (`mov`, `add`, `cbne`). A multi-register instruction writes its destination last: `add src, rd`, `xnorpop ra, rb, rd`, `setlt ra, rb, rd`, and the atomics `aadd rs, (ra), rd` and `ll (ra), rd`.
- **Compare and branch.** There are no condition codes, so every decision is a compare-and-branch. `cbCC rd, $imm, label` compares `rd` with a signed immediate of at most 16 bits and branches on the condition: `cbeq r3, $5, label`; `cbCC ra, rb, label` compares two registers, and `cbeq` and `cbne` against zero have the two-byte form. The mnemonics are `cbne cbeq cbcc cbcs cbge cblt cbgt cble cbhi cblos`, with `cbhis` for `cbcc` and `cblo` for `cbcs`. The assembler chooses among the forms by the size of the immediate and the distance (the widths are in 9.10.5); when no form reaches, a label beyond 16 MB or in another object file, it writes the opposite `cbCC` over a `br` to the label; nothing is written by either. `fcbCC ra, rb, label` (`fcbeq.f32 fcbne fcblt fcble fcbuo fcbor`, with `fcbgt.f32` and `fcbge.f32` the same with the registers exchanged, and the letter `f` for binary32, as in `fcblt.f32 ra, rb, label`, the same as the mark `.32` on both registers) compares two floating-point registers and branches, and is refused for a label that no form reaches (9.10.8). `setCC ra, rb, rd` and `setCC ra, $imm, rd` write 1 or 0 into `rd` from a comparison, for `seteq setne setlt setle setgt setge setcs setcc sethi setlos` (also `setlo` and `sethis`) (9.7.5). `ror.s32 rs, $n, rd` rotates the low 32 bits right and sign-extends the result.
- **Width and kind suffixes.** The machine's word is 16 bits, as the PDP-11's was, and an operation says how many bits it works on, and of what kind, as a dotted suffix of its mnemonic: `.s8 .s16 .s32 .s64` are signed integers, `.u8 .u16 .u32 .u64` unsigned integers, and `.f16 .f32 .f64` the floating-point formats `binary16`, `binary32` and `binary64`; the number is in bits, and `.f8` is refused as no such format. A suffix on a mnemonic names the width and the kind that the operands do not show: a memory operand has no width of its own, and a register holds no format. Where a suffix on the mnemonic is not enough, the formats are written on the operands, as in `fcvt r1.f16, r2.f32`. A bare mnemonic is the default, 64 bits, and the same word as its explicit spelling: `mov` is `mov.s64`, `aadd` is `aadd.s64`, `fadd` is `fadd.f64`. The suffix is on the word, so it is on every operand at once and no operand carries a mark, except those of `fcvt`, which has two formats (below). The words that take a suffix are these. `mov` takes the eight integer spellings: `mov.s8 (r1), r2`, `mov.u16 (r1), r2` and `mov.s32 r2, 4(r1)` load and store 8, 16 and 32 bits, a load sign-extends (`.s`) or zero-extends (`.u`), a store does not extend, so `mov.u8 r1, (r2)` and `mov.s8 r1, (r2)` are the same instruction, and between registers `mov` is the conversion set: `mov.s8 r1, r2` sign-extends the low byte and `mov.u32 r1, r1` zero-extends the low 32 bits. A constant has no width, so `mov.s8 $5, r1` is refused. `mov.user` (the suffix `.user` before the kind: `mov.user.s8`, `mov.user.u16`, and `mov.user` for 64 bits) checks its memory operand as a user access and needs one. `bswap` takes `.s16 .u16 .s32 .u32` (the bytes of each 16-bit word or 32-bit long), `ror` takes `.s32` with a constant count (the result is sign-extended, so `ror.u32` is refused), `div`, `mod`, `mulh`, `min` and `max` take `.s64` or `.u64` for the signed and the unsigned operation (`div.u64`; `mul.u64` is `mul`), and the atomics take `.s32` for the 4-byte word and the 64-bit spellings for the 8-byte (`aadd.s32 r1, (r2), r3`): the old value of a 4-byte atomic comes back sign-extended, so `.u32` is refused on `cas`, `swap`, `aadd`, `aand`, `abis`, `axor` and `ll`, while `sc.s32` and `sc.u32` are the same word and `amax` and `amin` take both kinds, for the kind is the comparison (`amax.u32` returns the old value sign-extended). The floating-point words take `.f32` for single precision and `.f64` for double: `fadd.f32`, `fsub.f32`, `fmul.f32`, `fdiv.f32`, `fsqrt.f32`, `fmadd.f32`, `fnmsub.f32`, `fabs.f32`, `fneg.f32`, `fclass.f32` and the eight `fcbCC.f32` (`fmin`, `fmax`, `fcopysign` and `frint` take `.f64` only). `fcvt` has two formats, so one suffix cannot name both and the formats are written on the operands, directly after a register, the source first and the destination last: `fcvt r1.f16, r2.f32` converts the half in `r1` to a single in `r2`, `fcvt r1.s32, r2.f32` a signed 32-bit integer to a single, `fcvt r1.f32, r2.s32` a single to a signed integer, `fcvt r1.s64, r2.f64` a signed 64-bit integer to a double and `fcvt r1.f64, r2.s64` a double to a signed integer; there are fourteen conversions: `fcvt r1.s64, r2.f64`, `fcvt r1.u64, r2.f64`, `fcvt r1.s32, r2.f32`, `fcvt r1.f64, r2.s64`, `fcvt r1.f64, r2.u64`, `fcvt r1.f32, r2.s32`, `fcvt r1.f64, r2.f32`, `fcvt r1.f32, r2.f64`, `fcvt r1.f32, r2.f16`, `fcvt r1.f16, r2.f32`, `fcvt r1.f64, r2.f16`, `fcvt r1.f16, r2.f64`, `fcvt r1.f16, r2.s32` and `fcvt r1.s32, r2.f16`; the common conversion, an integer to a float of the same width, has a short form with one suffix on the mnemonic, `fcvt.s64 r1, r2`, `fcvt.u64 r1, r2` or `fcvt.s32 r1, r2` (the same as `fcvt r1.s64, r2.f64`, `fcvt r1.u64, r2.f64` and `fcvt r1.s32, r2.f32`), which is what compilers write and the disassembler prints, and every other conversion is written with the marks. A register mark is a suffix of a register's name, `r0` to `r31`, `sp` or `fp`, and of nothing else, and only `fcvt` takes one: every other instruction refuses it, for its width is a suffix of its mnemonic. A conversion carries a mark on both operands, so `fcvt r1, r2`, `fcvt r1.f32, r2` and `fcvt.s32 r1, r2.f32` (a short form with marks) are refused, and so is a value mark where a register is wanted (`fcvt buf.f32, r2`). A pair with no instruction (`fcvt r1.s32, r2.f64`, anything with `.u32` or `.s8`) is refused with the two-instruction way: a 32-bit integer and a double have no instruction between them, so `fcvt r1.s64, r2.f64` on a register that holds the sign-extended integer converts one, and `mov.u32 r1, r1` makes an unsigned 32-bit value first. Where the kind means nothing (a store, `bswap`, the 64-bit spellings) `.s` and `.u` are accepted and are the same instruction. With `(r1)+` and `-(r1)` and no stride, the stride is the size the suffix names: `mov.s8 (r1)+, r2` steps by one byte. A word with a suffix it does not take is an error that names the word and the suffixes it takes (`mov.s9`, `fadd.f8`, `aadd.s16`); the vector words keep their lane letters (`vadd.f`, `vld.b.l`).
- **Value marks.** A number or a symbol can say how many bits its value has and how to read them, with a dotted mark that has the letters of the suffix of a mnemonic: `.s`, `.u` or `.f`, and a width of 8, 16, 32 or 64 (`0xff.s8`, `limit.u16`, `$0xff.u8`, `.word table.s16`, `cbeq r1, $0x7f.s8, 1f`). I wrote it for the values that are a pattern of bits: `0xff` is a byte of ones, and whether it is 255 or minus one depends on how it is read, which C leaves to the type of the place it lands in and which here the mark can say. A mark is written only where the value deviates from the default, which is the value as written, at its full width. The value has to fit as either reading of the width, signed or unsigned, and a value that fits neither is refused; then the low bits of the width are read as the kind says: `.s` sign-extends them, `.u` zero-extends them, and `.f` passes the bits through unchanged (it converts nothing and names no instruction: it says that the bits are a floating-point value's). At 64 bits every value fits and nothing changes. The mark binds to the number with its sign, so `-1.u8` is 255 and `-1.s8` is -1; it follows a number or a name only, so `(a-b).u8` is not written. A mark on a symbol needs the value of the symbol at assembly time, a constant (`limit = 0x1ff`, before or after the use); a label or an external symbol is an address, there is no relocation that checks a range of 8 or 16 bits, and the assembler refuses the mark on it. A name that ends in a dot, a kind letter and a width (`buf.u8`, `x.s8`) is reserved for the mark and cannot be defined, assigned or declared; `tmp.s7` and `.32` are ordinary names, and a name written in double quotes (`"x.s8"`) is allowed.

  | `0xff.u8` | 255 |
  | `0x80.s8` | -128 |
  | `200.s8` | -56 |
  | `-1.u8` | 255 |
  | `-128.u8` | 128 |
  | `0xffff.s16` | -1 |
  | `65535.s16` | -1 |

- **Literal pool: `=expr`.** An operand written with a leading `=` is syntactic sugar for a pooled constant and has no other meaning: `mov =0x123456789ABC, r1` puts the 64-bit value in the literal pool and loads it with
  one PC-relative `mov`. It is accepted where a quad memory source is (`mov`, `push`, the ALU group and the floating-point ALU ops), and refused with a width suffix (`mov.s8 =K, r1`), and for shifts, stores,
  `lea` and a relocatable symbol. `=` always pools, even a small value; use `$imm` for a constant that fits the signed 32-bit field. A bare `$K` that no form of the instruction holds is an error (use `=K` to load it from the literal pool; `mov $K, rd` holds any 64-bit constant):
  the assembler never pools silently. Entries are 8 bytes, 8-byte aligned, one per distinct value per pool, in order of first use, emitted into `.text` at the end of the section or at the directive **`.pool`** (flush now; code must
  jump over a mid-section pool). The `=` marks the sugar on the page, which is why it is allowed.
- **Length.** The assembler chooses the shortest form: the first form in the table's order, shorter first and then the order of the catalogue in the grammar, whose fields can hold the operands. Lengths only grow from one pass to the next, and every distance is measured on the layout of the previous pass. The one-parcel forms have no mnemonics of their own, so `mov (r3), r1` assembles to the one-parcel form when it fits and to a longer form when it does not. An unresolved symbol needs a form with a field of 32 bits or more and a relocation, and the linker shortens it, or lengthens it, when it knows the address.

- **One word names the operation.** A word never says how many bytes its encoding has: `mov $imm, rd` is two, four, six or ten bytes by the constant, `trap $n` is two bytes for every `n` from 0 to 255, `br label` takes the one-, two- or three-parcel form by the distance, and `jmp label` is `br label`. The operand-size suffixes are not lengths and stay: `mov.s8`, `mov.s16`, `mov.s32` and `mov` move 1, 2, 4 and 8 bytes, and `aadd` and `aadd.s32` add 8 and 4. A suffix is the width of the operation, not a different operation: `mov.s8 (r1), r2` and `mov` are the one `mov` with another width of its memory operand, and `aadd.s32 r1, (r2), r3` and `aadd r1, (r2), r3` the one `aadd`. A word that does a different thing stays a different word: the fused `mov2` and `movcall` do two things in one, `cbCC` compares and branches while `setCC` compares and writes 0 or 1, and `sob` subtracts one and branches while `dec` only subtracts.

- **`.encode N`.** A test that wants one particular form writes `.encode N` before the instruction: from there on every instruction is assembled in the shortest form of N parcels (two bytes each) or more that takes its operands, until `.encode 0` (or `.encode` alone) restores the shortest form. `.encode 5` before `mov $5, r1` writes the ten-byte form; `.encode 3` writes `mov $5, r1` as the six-byte form with a 32-bit immediate. A form of that many parcels that the operands cannot use is an error. An object that uses `.encode` is not shortened by the linker, so the forms stay as written.

- **Invocation.** `as64 [--no-relax] [--stats] [--dump-lens file] [-o obj] file.s`; `ld64 [-M] [-o out] [-e entry] [-Ttext addr] [--no-relax] [--stats] [--dump-map file] objects...`; `sim64 [options] program` runs the executable. There is one machine, so no option selects an encoding and no field of the object names one: the `e_flags` of an executable are zero, and `ld64` and `sim64` refuse a file with a bit set that this appendix does not define. `--stats` prints the instruction counts and bytes, `--dump-lens file` writes the length chosen for every instruction, and `--no-relax` (for `as64` and for `ld64`) gives the plain object and links an object as the assembler laid it out.

- **Words of the pdp64.** The user-qualified moves `mov.user` and the others of 9.6.9, which take the kinds and widths of `mov` after `.user` (`mov.user.s8 (r1), r2`, `mov.user.u16 (r1), r2`); the fused `movcall rs, rd, label`, `popret rd`, `popmret $mask` and `mov2 ra, rb, rc, rd`, which the assembler never chooses for itself; `pushm`, `popm` and `popmret` take a mask. `(r)+` and `-(r)` without a stride write stride 0, which means the size of the access, and `(r)+8` writes 8. `extb`, `extzb` and `insb` have a 6-bit position and width, so a width of 64 is refused. The 22 meaningless shapes the first assembler accepted (`clr $imm`, `jmp $imm`, a store to an immediate, `lea $imm` and the others) are refused.
- **Relaxation objects.** By default the assembler marks an object (`e_flags` 0x10, `EF_PDP64_RELAX`) and gives every instruction that holds the address of a symbol a relocation, local symbols included, and every padding of `.text` an `R_PDP64_ALIGN` (type 6; addend = padding bytes << 32 | alignment); the linker then gives each such instruction the shortest form that reaches. An object whose `.text` holds a distance that is not a relocation (a difference of two labels used as a number, a `d(pc)` written as a number) is marked `EF_PDP64_NOADJ_TEXT` (0x20) and its `.text` is left alone. A `cbCC` that the assembler expanded to the opposite branch over a `br` stays expanded. `--no-relax` opts out.

- **Object format.** ELF64, little-endian, `e_machine` 0xF064 (`EM_PDP64`); relocations `R_PDP64_D64`, `R_PDP64_D32`, `R_PDP64_INSN_ABS`, `R_PDP64_INSN_PC`, `R_PDP64_INSN_BR` (`as64/relocs.h`; LLVM: `ELFRelocs/PDP64.def`).

What it leaves out of V7 `as`: octal numbers by default (a number with a leading zero is an error that names `0o`), `<string>` and the `'\e` escape, `\/ \< \>`, `.stabs`,
symbols cut to eight characters.
